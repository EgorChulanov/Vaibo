## 1. Домен vaibofood.ru (reg.ru)

**Сейчас домен не заработает.** В личном кабинете reg.ru висит «Ошибка при идентификации». Для доменов .ru и .рф администратор обязан подтвердить личность через Госуслуги; пока это не сделано, домен не делегируется.

1. reg.ru → домен → «Узнать подробнее» → повторить идентификацию через Госуслуги.
2. Проверить, что ФИО и паспорт в профиле reg.ru совпадают с Госуслугами буква в букву (частая причина ошибки: «е» вместо «ё», старый паспорт).
3. Если снова ошибка, написать в поддержку reg.ru со скриншотом.

### DNS для GitHub Pages

reg.ru → домен → «DNS-серверы и управление зоной» (оставить ns1.reg.ru / ns2.reg.ru) → ресурсные записи:

| Тип | Имя | Значение |
|---|---|---|
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | egorchulanov.github.io. |

Потом GitHub → репозиторий → Settings → Pages: Custom domain `vaibofood.ru`, после выпуска сертификата включить **Enforce HTTPS**. DNS обновляется от нескольких минут до суток.

### Хостинг: что важно знать

GitHub Pages подходит для **сайта-витрины**: на нём нет форм и нет персональных данных. Данные пользователей **приложения** (аккаунты, вес, рост, история меню) должны храниться на серверах в России (ч. 5 ст. 18 152-ФЗ): Yandex Cloud, Selectel, VK Cloud, Timeweb и т. п.

Если позже на сайте появится форма (подписка, заявка) или Яндекс Метрика, сайт лучше перенести на российский хостинг. Файлы из папки `site/` переносятся как есть.

## 3. Обязательное по закону (до запуска)

- [ ] **Уведомление в Роскомнадзор** об обработке персональных данных, до начала сбора. Подаётся на pd.rkn.gov.ru или через Госуслуги. Без него штраф, а номер в реестре потом указывается в политике.
- [ ] **Политика обработки ПДн** опубликована на сайте и в приложении (`/legal/privacy.html`).
- [ ] **Согласие на обработку ПДн отдельным документом** (с 1 сентября 2025 его нельзя прятать внутри оферты): `/legal/consent.html`, в приложении отдельная галочка, не отмеченная заранее.
- [ ] **Данные россиян хранятся в РФ** (хостинг приложения).
- [ ] **Оферта** с понятными условиями автопродления подписки и отмены: `/legal/offer.html`.
- [ ] **Сведения о продавце** (наименование, ОГРН, адрес) на сайте: `/contacts.html`. Этого требует Закон о защите прав потребителей.
- [ ] **Не называть Vaibo медицинским.** Если приложение «лечит», «назначает диету при диабете» и т. п., оно может считаться медицинским изделием и потребует регистрации в Росздравнадзоре. Поэтому на сайте формулировки «планирование питания», а не «лечебное питание». Это касается и описаний в сторах, и рекламы.
- [ ] **Не собирать диагнозы.** Сведения о здоровье относятся к специальной категории данных с особыми требованиями. Аллергии лучше оформлять как «исключить продукты», без привязки к болезни.
- [ ] **Cookies и Метрика.** Сейчас сайт ничего не отслеживает. Если подключите Яндекс Метрику, обновите `/legal/cookies.html` и сделайте баннер с выбором. Google Analytics не используйте: это трансграничная передача данных.
- [ ] **Рекомендательные технологии.** Подбор меню алгоритмом может подпадать под ст. 10.2-2 закона 149-ФЗ (правила применения рекомендательных технологий нужно публиковать). Уточнить у юриста; черновик уже есть в соглашении, раздел «Рекомендации».
- [ ] **Реклама.** Любая платная реклама в интернете маркируется через ОРД (токен erid).
- [ ] **Товарный знак «Vaibo»** в Роспатенте. Классы: 9 (приложение), 35 (сервис корзины), 42 (SaaS), 43/44 по совету патентного поверенного. Плюсы: защита от копий, проще пройти модерацию в сторах, и латинское название на вывесках и в интерфейсе законно используется как зарегистрированный знак (с 1 марта 2026 ужесточены требования к русскому языку в информации для потребителей).

У конкурентов на сайте три плашки: **участник Московского инновационного кластера**, **реестр стартапов и высокотехнологичных компаний Москвы**, **аккредитованная ИТ-компания Минцифры**.

### Порядок (без лишней бюрократии)

1. Открыть ООО → уведомление в Роскомнадзор → подать заявку на товарный знак.
2. Регистрация на i.moscow (кластер) → заявка в реестр стартапов Москвы.
3. Первая выручка и сотрудники → аккредитация Минцифры.
4. Реестр российского ПО → заявки в ФСИ и Сколково.
5. Когда статусы получены, добавить плашки в подвал сайта. **Не ставить плашки до получения статуса**: это недостоверная реклама.

## 5. Как выложить сам проект приложения на GitHub

Папки `Vaibo`, иконки и `pack` лежат у вас на компьютере, облачная сессия к ним доступа не имеет. Чтобы добавить их в этот репозиторий:

```bash
cd ~/Desktop/Vaibo
git clone https://github.com/egorchulanov/vaibo.git vaibo-repo
cp -R <папка проекта> vaibo-repo/app
cp -R <папка с иконками> vaibo-repo/brand
cd vaibo-repo
git add app brand
git commit -m "Add app source and brand assets"
git push
```

Перед `git add` проверьте, что в папке нет `.env`, ключей API, паролей и файлов `GoogleService-Info.plist` / `google-services.json` с секретами.
